## Главный сценарий

Сайт также ищет по подключённым заметкам. Введи слово или фразу, нажми «Найти» и открой нужный фрагмент с подсветкой в исходном Markdown. Поиск перечитывает выбранные файлы. Открытый черновик остаётся привязан к своему Inbox. [Как пользоваться поиском](docs/GETTING_STARTED.md#поиск-в-050)

1. Владелец добавляет мысль с телефона, сайта или панели ноутбука.
2. Запись появляется в существующем Obsidian vault на Google Drive.
3. Подключённый помощник читает её, сохраняет результат обработки в нужную заметку.
4. Обновлённые данные видны на сайте, телефоне и виджетах после обновления.

Для этого не должен требоваться постоянно включённый домашний ноутбук. Сайт и приложения используют общие данные; Obsidian остаётся привычным редактором и хранилищем заметок.

## Решение владельца от 25.11.2026

**Google Drive — общий источник заметок. Сначала делаем обычный сайт для ноутбука; Android и все виджеты — после полезной веб-версии.**

- Сайт читает и изменяет выбранные Markdown-файлы непосредственно через Drive API.
- Будущий Android отдельно получает разрешение Google и работает с теми же файлами; доступность сайта для этого не нужна.
- Помощник использует собственное разрешённое подключение Drive. Появление записи само по себе не запускает модель.
- Формат заметок и правила записи общие. Отдельная серверная база с копией заметок для первого этапа не нужна.
- Если используется Google Calendar, события остаются в Calendar: Drive не заменяет его API.

## Что входит в замысел

- Сайт для телефона, домашнего ноутбука и разрешённого доступа с рабочего браузера.
- Android-приложение с быстрым вводом, меню «Поделиться» и настоящим виджетом главного экрана.
- Компактная панель дня на рабочем столе Windows.
- Календарь, выбранные дела, текущие приоритеты, планы, поиск и чтение заметок.
- Изменение общих данных пользователем и моделями; понятный результат обработки.
- Несколько облачных провайдеров и API-ключей, позже — эксперимент с локальными моделями Android.

## Что запоминает сайт

- В новом профиле браузера включён общий режим. Настройки и черновик живут в памяти вкладки.
- Флажок **«Запомнить на личном устройстве»** сохраняет ограниченный ключ Picker, номер проекта, ID и имена выбранных заметок, текущий выбор и черновик с момента ввода. При следующем посещении достаточно нажать **«Подключиться снова»**. Google при необходимости покажет окно подтверждения.
- Если в Drive уже есть точная запись с меткой черновика, чтение автоматически подтверждает доставку и очищает поле. Если отправка прервалась до доставки, нажми **«Проверить и повторить»**. Запись привязана к исходному файлу.
- Обзор запоминает выбор источников вместе с настройками личного устройства. Текст карточек хранится в памяти открытой вкладки до выхода из Drive. Обе карточки показывают время своего последнего чтения.
- Запрос, результаты поиска и открытый фрагмент живут в памяти вкладки до очистки, выхода или перезагрузки. Текст запроса обрабатывается в браузере. В Drive уходят запросы чтения выбранных файлов по ID.
- **«Забыть это устройство»** отключает Drive и удаляет местные данные My Day, включая старый черновик 0.1.1. Файлы в Drive сохраняются. Токен Google хранится только в памяти. Содержимое прочитанной заметки сайт в браузерное хранилище не копирует.

Через **«Выбрать файл»** можно открыть существующий `Мысли.md` для быстрой записи, `Now.md` и `To Do now.md` для чтения. Каждый файл выбирается отдельно. Для проверки подключения по-прежнему подходит `My-Day-test.md` с заголовком из шаблона.

## Первый рабочий шаг (результат)

Владелец выбрал существующий Default Gemini Project из-за лимита проектов и сообщил о настройке двух API и OAuth. Тестовый интерфейс на GitHub Pages прошёл основной сквозной сценарий; ключ Picker вводится на странице, не хранится в репозитории.

Первый проход: кнопка «Подключить Google Drive» → выбор одного тестового Markdown-файла → чтение → добавление мысли → повторное чтение. Затем помощник отдельно читает/правит этот файл, а сайт получает изменение по кнопке обновления. Основная проверка выполняется в браузере ноутбука, без локального сервера и зависимости от запущенного Obsidian.

Первый вариант использует краткоживущий Google access token в браузере. После истечения доступа потребуется действие пользователя для повторного подключения; закрытая страница сама не продолжает работать.

После проверки — полезный веб-экран. Android, виджеты, несколько моделей и локальный ИИ остаются самостоятельными поздними этапами.

## Размещение

Для первого сайта достаточно HTTPS-хостинга статических HTML/JS-файлов, совместимого с Google OAuth popup и Picker. Выбран GitHub Pages: https://ltstripes.github.io/My-day-/ . Доступ к частным заметкам защищается разрешениями Google; исходники страницы не содержат заметок или токенов.

Найден существующий публичный проект Health-Check в ChatGPT Sites: [health.ltstripes.com](https://health.ltstripes.com). Его наличие не обязывает делать My Day сервером для Android. Совместимость Google-подключения с выбранным хостингом проверяется отдельно. Рабочая тестовая версия опубликована через GitHub Pages; доступ к Google подтверждён на одном тестовом файле.

## Принципы

- Один владелец, небольшие понятные изменения и проверки по реальному риску.
- Существующая схема Google Drive + Git для Obsidian сохраняется.
- Защита от потери черновика и дублирующей отправки без сложной многопользовательской синхронизации.
- Исходный текст сохраняется; предложения модели отделяются от принятых дел.
- В репозитории — код, спецификация и синтетические примеры. Личные заметки, ключи и токены хранятся отдельно.
