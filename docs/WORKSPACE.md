# Рабочая папка My Day на Windows

Открой в Проводнике `D:\My day`. Там лежат код сайта, тестовая копия и каталоги исполнителей. Заметки по-прежнему хранятся на Google Drive.

| Где | Для чего |
| --- | --- |
| `D:\My day\AGENTS.md` | Вход для любого агента. Ведёт к действующим правилам в репозитории. |
| `D:\My day\main` | Постоянная копия ветки `main`. Из этой ветки GitHub Pages публикует сайт. |
| `D:\My day\test` | Постоянная независимая копия для проверок. При обычном обновлении указывает на коммит из `origin/main` в режиме detached HEAD. Для проверки записи на Drive используется тестовый Markdown. |
| `D:\My day\projects\<источник>\<задача>` | Отдельная копия Git для исполнителя. Например, `projects\codex\workspace-setup`. Папка другого источника появится при его первой задаче. |
| `D:\My day\quarantine\ГГГГ-ММ-ДД\<источник>\<задача>` | Целиком перемещённая копия вместе с файлами и историей Git. Сохраняется до решения владельца. |

## Начать задачу

Агент сам создаёт рабочую папку. Команда для задачи с именем `notes-search` выглядит так.

```powershell
& 'D:\My day\main\tools\workspace\New-MyDayWorkspace.ps1' -Source codex -Task notes-search
```

Скрипт берёт свежую ветку `origin/main`, создаёт независимый клон и ветку `work/codex/notes-search`. Параметр `-BaseRef 'origin/имя-ветки'` позволяет выбрать другую опубликованную ветку. Повторный запуск с теми же именами возвращает существующую рабочую папку. Для двух параллельных задач используй разные имена. В этой структуре можно так же работать из другого чата или редактора.

Ведущая модель определяет сложность работы. Простые изменения, документацию и независимые проверки можно отдавать быстрой модели. Для работы с доступом, черновиками и файловыми операциями подходят модель с сильным рассуждением и отдельная проверка результата. Ведущая модель отвечает за интеграцию и проверку на рабочем адресе.

## Карантин и восстановление

Планировщик Windows запускает `MyDay-WorkspaceQuarantine` ежедневно в **19:00 по местному времени** от имени вошедшего пользователя. После пропущенного запуска Windows выполнит задачу при ближайшей возможности. Для проверки расписания открой **Пуск → Планировщик заданий → Библиотека планировщика заданий → MyDay-WorkspaceQuarantine**.

Кандидатом становится только клон из `projects`, созданный штатным скриптом, после семи полных суток без изменений. Скрипт проверяет рабочие файлы, служебные признаки Git, незавершённые операции, stash, HEAD и локальные ветки. Неучтённые материалы, включая старые `.local`, `.env` и логи, удерживают копию. Воспроизводимые зависимости корневого `node_modules` могут переехать вместе с ней. Состояние проекта сверяется локально. Занятое место назначения, ссылка на другой каталог или несовпадение источника Git с основной копией оставляют папку на месте. Проверка повторяется перед переносом. Постоянные `main` и `test` и каталоги других проектов в обход не входят.

Если работа отложена, агент может оставить пустой файл `.git\my-day-keep`. Он удерживает копию столько, сколько нужно. Обычно факт завершения виден по истории `origin/main`. После squash-слияния агент может записать точный SHA локального HEAD в `.git\my-day-finished`, **только после проверки принятого PR**. С записи отметки снова отсчитываются семь суток. Отдельная ветка с незавершёнными коммитами сохраняет копию на месте.

Чтобы посмотреть решение для каждой папки, запусти команду без параметра `-Apply`. Она выводит `Kept` (остаётся) или `WouldMove` (готова к переносу).

```powershell
& 'D:\My day\main\tools\workspace\Move-InactiveWorkspaces.ps1'
```

Для восстановления открой в Проводнике нужную дату и источник внутри `quarantine`. Убедись, что исходное имя в `projects\<источник>` свободно, и перенеси туда **всю папку задачи**. Если имя занято или восстановленная работа должна остаться надолго, попроси агента восстановить копию отдельно и поставить отметку `my-day-keep`.

## Обновить постоянные копии и расписание

При первоначальной настройке скрипт запускается из скачанного репозитория. При следующем запуске он обновит чистую основную и тестовую копии до `origin/main` и сохранит папки с локальной работой. Существующий корневой `AGENTS.md` сохраняется.

```powershell
& 'D:\My day\main\tools\workspace\Initialize-MyDay.ps1'
```

После переустановки Windows агент может вернуть расписание одной командой из учётной записи владельца.

```powershell
& 'D:\My day\main\tools\workspace\Install-MyDayQuarantineTask.ps1'
```

## После продуктового релиза

Ответственный за выпуск дожидается успешной публикации Pages и открывает действующий сайт. Затем он обновляет [текущий статус](STATUS.md) и связанную GitHub-задачу, указывает версию, дату, PR, ссылку на публикацию, фактические проверки и ближайший шаг для владельца. Результат проверки с тестовыми ответами и результат с настоящим аккаунтом отмечаются отдельно. Обновление одного лишь отчёта сохраняет текущую версию сайта.
