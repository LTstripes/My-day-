# Представления заметок в My Day

Дата: 26.11.2026. Основание — пожелание владельца: разные типы Obsidian-заметок показывать в приложении и на сайте как список, график, карточку или напоминание.

В 0.16.0 реализованы этапы A–D. Для выбранной заметки доступны временный и сохранённый виды, график по таблице и карточка внимания по явно указанной дате.

Первая задача реализации: [#29 — выбор вида чтения](https://github.com/LTstripes/My-day-/issues/29).

## 1. Результат для владельца

Заметка остаётся обычным Markdown в существующем Obsidian vault на Google Drive. My Day получает актуальный файл и показывает его подходящим способом. Один источник может иметь несколько представлений: например, план поездки — полный текст, список подготовки или карточка следующего действия.

Ключевой пользовательский маршрут:

1. Выбрать разрешённую заметку в Drive.
2. Открыть **«Показать как…»** и выбрать доступный вид.
3. Посмотреть результат, в любой момент вернуться к полному тексту.
4. Чтобы использовать этот вид при следующем открытии, нажать **«Сохранить вид в заметке»**. Другой авторизованный клиент My Day получит выбор при чтении того же файла.

Смена вида сама по себе не меняет содержимое и не запускает модель.

## 2. Три независимых понятия

| Понятие | Пример | Назначение |
| --- | --- | --- |
| Роль источника | Inbox, текущий контекст, список дел, план, обычная заметка | Куда направляется действие приложения и какие операции в нём предусмотрены |
| Тип содержимого | План, справка, дневник, измерения, коллекция | Как понимать структуру |
| Представление | Текст, список, карточка, таблица, график, хронология | Как показать содержимое |

Тип или вид не назначают файл новым Inbox/To Do now и не дают право редактирования. Возможности Google Drive, явная роль источника и поддержанные приложением операции проверяются отдельно.

План с датой может одновременно отображаться карточкой и попадать в напоминания. Напоминание — дополнительное поведение, а не обязательный отдельный тип заметки.

### Справочник типов заметок

| Тип содержимого | Что лежит в заметке | Подходящий вид в первой версии |
| --- | --- | --- |
| Список | Покупки, сборы, дела, обычные пункты и флажки | **Список** показывает пункты всех разделов и состояния флажков. |
| План | Проект или поездка с шагами | **План** показывает первый открытый флажок. **Список** даёт посмотреть остальные шаги. |
| Справка | Инструкция, рецепт, набор фактов | **Текст** сохраняет абзацы и заголовки. |
| Дневник | Датированные записи и наблюдения | **Текст** для чтения записей по порядку. |
| Коллекция | Подборка книг или фильмов | **Список** для маркированных записей или **Текст** для остального. |
| Журнал измерений | Таблица дат, значений и единиц | **График** по выбранным колонкам и исходная таблица. |

Одна заметка может подходить под несколько строк. Для подключения достаточно обычного Markdown. Необязательный `myday_kind` описывает содержимое. `myday_view` задаёт начальный вид. Дата внимания может дополнять любой тип.

## 3. Какие виды нужны

Все примеры ниже синтетические; они не являются данными владельца.

| Источник | Подходящий вид | Какие данные необходимы |
| --- | --- | --- |
| Покупки, сборы, повседневные дела | Список с группами и состоянием checkbox, если оно есть | Обычные Markdown-пункты и чекбоксы; идеи не становятся задачами автоматически |
| Проект или поездка | Карточка плана, список шагов; позже маршрут по дням | Заголовки, пункты и явно указанные даты |
| Книги, фильмы, другие подборки | Таблица или карточки | Название и свойства записей; оценка только если она указана |
| Чтение или иной журнал чисел | Таблица и график | Явные даты, числовые значения и единицы |
| Справка | Читаемый текст или карточка фактов | Абзацы, заголовки, явно выделенные поля |
| Заметка с датой внимания | Карточка «Скоро / Сегодня / Просрочено» | Явно заданная дата; для точного времени — часовой пояс |

Представление для коллекции записей внутри одного файла и подборка многих файлов — разные возможности. Первый этап работает с одним выбранным Markdown. Агрегация всего vault, правила по папкам/тегам, граф связей и полный импорт Bases не входят в него.

## 4. Где хранить выбор

Основной способ — необязательные плоские свойства Obsidian в YAML-frontmatter. Это переносимые данные внутри той же заметки, а не отдельная серверная копия.

Минимальный пример:

```markdown
---
myday_view: list
---

# Подготовка к поездке

- [ ] Проверить документы
- [ ] Скачать билеты
- Уточнить удобный маршрут
```

Тип содержимого можно указать отдельно, когда он полезен:

```yaml
myday_kind: plan
myday_view: list
```

**Поля `myday_*` принадлежат My Day.** Владелец может сохранить вид кнопкой в интерфейсе.

Поддержаны значения `myday_view` `text`, `list`, `plan` и `chart`. При неизвестном значении открывается текст.

### Приоритет выбора вида

1. Временный выбор пользователя в открытом просмотре.
2. Проверенный `myday_view` из файла.
3. Известное значение по умолчанию для роли или поддержанного типа.
4. Обычный текст.

Существующие Now, To Do now и Inbox продолжают работать без новых свойств. Для неизвестной заметки приложение может предложить вид по понятной структуре, но не записывает догадку автоматически. Не требуется вызов модели при каждом открытии.

### Несколько устройств

Общий вид по умолчанию хранится в файле. Временное переключение действует только в текущем просмотре. Не вводить параллельно второй общий JSON-реестр с конкурирующей копией тех же настроек.

Другой клиент должен иметь собственный доступ к файлу и реализованную поддержку вида. Сохранение свойства не выдаёт разрешение Google, не подключает весь vault и не создаёт Android-приложение. Если вид ещё не поддержан, клиент показывает текст.

Если запись запрещена, временный просмотр работает. Интерфейс не обещает, что такой выбор запомнился на других устройствах.

## 5. График: данные должны быть определены

Первая реализация графика — одна явно выбранная Markdown-таблица, например:

```markdown
| date | pages |
| --- | ---: |
| 2026-11-20 | 18 |
| 2026-11-21 | 24 |
| 2026-11-22 | 14 |
```

При настройке выбери таблицу, колонку X с датой, колонку Y с числом и единицу измерения. При сохранении My Day запишет `myday_chart_table` (заголовок раздела и столбцы выбранной таблицы), `myday_chart_x`, `myday_chart_y` и `myday_chart_unit`. Если таблица перестала определяться однозначно, приложение предложит выбрать её заново.

- Исходная таблица остаётся доступной рядом с графиком.
- Отсутствующее значение не превращается в ноль.
- Непонятные числа, даты, повторные даты и несколько возможных таблиц не интерпретируются молча: нужен явный выбор/объяснение.
- Для даты без времени сохраняется календарный день, без случайного сдвига через UTC.
- Фильтрация и агрегирование, если появятся, обозначаются явно.
- Модель может по запросу предложить структуру из свободного текста с опорой на исходные значения. Предложение не подменяет факты и не сохраняется как установленная история без согласованного действия.
- Не переносить базы и расчёты Hermes Finance или Health-Check только ради графика. Их возможное подключение — отдельный источник с собственными правилами.

График числового ряда и граф связей заметок — разные виды. Для графа связей позднее потребуются разбор ссылок, доступные цели и отдельная проверка полезности.

## 6. Напоминания: сначала карточка

На «Сегодня» в разделе «Требуют внимания» появляются зарегистрированные через «Читать заметку» файлы со свойством `myday_attention`. Допустимы календарная дата `2026-11-26` и точный момент с часовым поясом, например `2026-11-26T17:00:00+03:00`. Видны просроченные даты, сегодняшний день и ближайшие семь дней. Нажатие открывает исходную заметку.

Дата без времени не получает выдуманный час уведомления. Для точного момента сохраняются однозначная дата/время и часовой пояс; отображение учитывает текущий пояс пользователя. Срок дела, время события и момент напоминания — разные значения, не выводить одно из другого молча.

Это ещё не системное уведомление при закрытой странице. Доставка требует отдельного механизма: например, разрешённого Web Push с service worker и отправителем либо нативного планирования на Android. Его выбор, разрешения и фактическая работа на устройстве проверяются отдельным этапом. Наличие нынешнего worker для F5 не делает его планировщиком.

Добавление этой концепции не создаёт расписаний, уведомлений или событий Google Calendar. Если позже используется Calendar, событие остаётся в Calendar, а не дублируется автоматически в Drive.

## 7. Минимальная реализация поверх 0.14

Достаточно небольшого слоя: разбор заметки → выбор вида → отрисовка заранее реализованного вида. Данные хранятся в Drive; обязательный backend для чтения и отображения не нужен.

### Общий путь чтения

[drive.js](../web/drive.js) читает выбранный Markdown для планов и библиотеки. Добавление мысли или дела требует соответствующей роли. Для сохранения вида есть отдельная операция с проверкой версии.

[device.js](../web/device.js) сохраняет ID и имя обычной заметки отдельно от источников дня. Профиль прежних версий сохраняет прежние роли, закрепление плана и оба черновика.

### Разбор и отрисовка

- Хранить исходный `raw` отдельно от свойств, тела и данных представления.
- Безопасно читать нужные плоские свойства YAML; не исполнять инструкции или код из заметки.
- Не сериализовать весь файл заново ради показа.
- Переиспользовать существующий разбор пунктов, чекбоксов, первого действия плана и безопасное отображение текста.
- Переключение представления не добавляет кнопки изменения произвольному файлу. Существующие действия To Do now остаются доступны только через назначенную роль и прежние проверки.
- Общий список не должен наследовать фильтр «только сегодня»: например, список книг показывает все выбранные пункты. Разбор структуры и фильтр дня различаются.
- Сохранить корректные смещения при переходе из поиска/очереди в исходный текст: скрытие свойств не должно смещать подсветку.
- Не наращивать все виды внутри `app.js`; выделить небольшой модуль представлений без универсального плагинного движка.
- Не исполнять DataviewJS, JavaScript, произвольные формулы или HTML из заметок. Неподдержанные блоки доступны в полном тексте.
- В смешанной заметке специальный вид показывает только распознанную часть и явно даёт открыть **всю заметку**. Нераспознанные абзацы не выдаются за отсутствующие.
- Ошибка свойств, несовместимый вид или недостаточные данные ведут к доступному тексту с понятным объяснением, а не к пустому экрану.

### Явное сохранение вида

Это отдельная узкая операция после нажатия пользователя: свежий read → проверка разрешения и версии/ETag → изменение только нужных свойств → readback. Не ослаблять guard существующих операций записи ради любого `myday_kind`.

Сохраняются Drive ID, тело, неизвестные свойства, комментарии, служебные маркеры, BOM и окончания строк. Неоднозначный/некорректный YAML не переписывается автоматически; остаётся временный просмотр. Если безопасное адресное изменение невозможно, показать причину без изменения исходника.

Старый `My-Day-test.md` обязан начинаться с `# My Day test`. Для испытания новых свойств нужны отдельные синтетические Markdown-файлы; добавление frontmatter в старый тестовый шаблон сломает его нынешнюю валидацию.

## 8. Этапы и приёмка

### A. Выбрать вид чтения

Произвольный разрешённый Markdown → **Текст / Список / План** → полный источник. Читать необязательный `myday_view`; старые заметки не требуют миграции. Этап A вообще не записывает свойства; сохранение появляется только в этапе B.

Готово, когда два разных синтетических источника показываются нужными видами, неоднозначный формат даёт текст, неизвестный файл корректно восстанавливается после входа, поиск и оба черновика сохраняются, а действия с делами/Inbox не расширились на произвольные файлы.

### B. Сохранить общий вид

Выбрать вид → явно сохранить в заметке → перечитать → открыть в другом разрешённом клиенте/профиле и увидеть тот же вид. Проверить сохранность остальных байтов, внешнюю правку перед сохранением и отсутствие ложного успеха при отказе записи.

### C. Один график

Одна выбранная таблица → явно настроенные оси → график и доступная исходная таблица. Критерии приёмки включают ноль, пропуски, неверный формат и обновление после внешней правки.

### D. Карточка внимания по дате

Явная дата у выбранной заметки → карточка на «Сегодня» → переход к источнику. Уведомления при закрытом сайте, повторяющиеся расписания и Android-виджеты — отдельные этапы.

Полная реализация Obsidian Bases/Dataview, массовая разметка vault, синхронизация папок и универсальный конструктор экранов в первые этапы не входят.

## 9. Источники

- [Obsidian Properties](https://obsidian.md/help/properties): свойства хранятся в YAML в начале Markdown; поддержаны текст, списки, числа и даты. Плоские свойства доступны обычному интерфейсу Obsidian.
- [Obsidian Bases](https://obsidian.md/help/bases): представления над файлами и их свойствами. Можно использовать совместимый подход к данным, но My Day не получает движок Bases автоматически.
- [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API): push-сообщения приходят от отправителя и обрабатываются service worker; сам Markdown не планирует уведомление.

Эти источники подтверждают свойства платформ. Описанная интеграция и имена `myday_*` — проектное предложение My Day.
