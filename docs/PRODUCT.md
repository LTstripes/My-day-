# My Day — концепция и требования

Редакция: 25.11.2026. Основание: прямые пожелания владельца. Это проектное описание, а не отчёт о готовой реализации.

## 1. Для чего нужен продукт

Одна понятная точка входа в личные планы и знания. Владелец смотрит день, записывает мысль и видит результат работы помощника с телефона, ноутбука и через разрешённый рабочий браузер.

Проект также нужен ради удовольствия от создания и практики разработки с ИИ. Его ценность измеряется удобством реальных сценариев и полученным опытом; он не обязан становиться сервисом для других людей.

## 2. Принятые требования

| Код | Требование |
| --- | --- |
| R01 | Сайт и Android-приложение используют одни данные. |
| R02 | Модель может обновлять заметки; обновления видны во всех клиентах после синхронизации. |
| R03 | Запись с телефона попадает в Google Drive и доступна подключённой модели для обработки. |
| R04 | Основные сценарии работают при выключенном домашнем ноутбуке. |
| R05 | Настоящий виджет Android нужен в первом Android-этапе. |
| R06 | Панель на рабочем столе Windows нужна на раннем этапе. |
| R07 | Сайт доступен с работы через браузер, если это допускают сеть и правила рабочего компьютера; личные данные закрыты входом. |
| R08 | Пользователь один. Не делать сложную систему одновременного редактирования. |
| R09 | Сохранить существующий Obsidian vault, Google Drive и Git, включая связь с рабочим компьютером. |
| R10 | Позже поддержать разных провайдеров моделей и собственные API-ключи. |
| R11 | Позже исследовать лёгкие модели непосредственно на Android. |

Новые регулярные уведомления не входят в первую версию. Это не ограничивает обновление информации внутри приложения и виджетов.

## 3. Экраны и поведение

### Сегодня

- Ближайшие события из подключённого календаря.
- Выбранные на день действия из существующего списка дел.
- Текущий фокус из Now; Now не превращается во второй список задач.
- Кнопка быстрой записи и время последнего обновления.
- Часовой пояс отображения учитывается явно, особенно в поездках.

### Заметки и ввод

- Свободный текст без обязательного названия, папки и тегов.
- Чтение выбранных заметок и поиск; полное воспроизведение всех плагинов Obsidian не требуется.
- Диктовка через клавиатуру телефона доступна как первый сценарий; собственная запись и расшифровка аудио — отдельное расширение.
- Ссылка, текст или изображение через Android «Поделиться».
- При плохой связи — локальный черновик и понятная повторная отправка.

### Планы

Поездки, личные проекты, покупки и другие выбранные материалы с ближайшим действием. Представления строятся поверх существующих заметок; вручную вести вторую копию этих планов не нужно.

### Помощник

- Новые записи, ожидающие обработки.
- Запуск разбора выбранной записи, затем автоматическая обработка при необходимости.
- Результат с ссылкой на исходную заметку: что добавлено, какой вопрос получил ответ, какая операция не удалась.
- Предложения модели и принятые действия различаются. Вопрос или идея не становятся обязательной задачей автоматически.
- Статус «готово» появляется после подтверждённой записи результата.

## 4. Общие данные

| Сущность | Основной источник |
| --- | --- |
| Исходные мысли и заметки | Существующие Markdown-файлы Obsidian на Google Drive |
| Текущий контекст и приоритеты | Now |
| Принятые действия | Существующий To Do now и согласованные тематические списки |
| События с датой и временем | Подключённый календарь; Google Calendar — первый кандидат |
| Статус доставки, настройки интерфейса, индекс | Небольшое служебное хранилище приложения |
| Код, требования и backlog | Этот GitHub-репозиторий |

Кэш и индекс можно пересобрать из источников. Ключи и OAuth-токены не входят в Obsidian или Git.

Предлагаемая схема: сайт / Android / Windows → общие операции приложения → Google Drive и календарь. Помощник работает с теми же файлами через разрешённый Drive-доступ либо через отдельные инструменты приложения. Конкретный транспорт для агентов выбирается после проверки возможностей размещения.

Приложение должно замечать изменения, сделанные моделью непосредственно в Drive, а не только собственные операции. Начальная стратегия: перечитывание при открытии, по кнопке обновления и допустимое периодическое обновление виджета. Мгновенная доставка через push — возможное расширение, не обещание первой версии.

## 5. Запись без лишней сложности

По уточнению владельца от 25.11.2026 сложная координация нескольких писателей не требуется.

Начальная схема сохраняет привычную точку входа `00 Inbox/Мысли.md`. Не вводить обязательный отдельный файл на каждую мысль без новой практической причины.

Минимальная защита:

1. Черновик сохраняется до сетевой отправки.
2. Перед изменением читается актуальное содержимое заметки, сохраняются её Drive ID и несвязанный текст.
3. У отправки есть устойчивый идентификатор: повтор после сетевого сбоя не создаёт вторую запись.
4. Операции самого сервиса выполняются последовательно для целевой заметки.
5. Если обнаружено изменение или неизвестен результат запроса, черновик сохраняется; сначала проверяется состояние источника.
6. После успешной записи показывается подтверждённый результат. Обновление локального Obsidian зависит от его обычной синхронизации.

Проверка версии не является универсальной атомарной блокировкой внешних клиентов. Для редкого конфликта достаточно сохранить несохранённый текст и показать понятное действие. CRDT, распределённые блокировки и сложный редактор слияния сейчас не нужны.

Существующий вечерний разбор можно использовать дальше. Видимость записи в Drive сама по себе не запускает модель: нужен ручной запуск, действующее расписание или явно реализованный обработчик. Новое расписание сейчас не создаётся.

## 6. Платформы и виджеты

### Веб

Адаптивный интерфейс для телефона и ноутбука. Устанавливаемая PWA удобна как дополнительный способ открытия. Первый полезный набор: день, выбранные заметки, запись мысли, обновление данных.

### Android

Предварительный кандидат: повторное использование веб-интерфейса через Capacitor плюс небольшой нативный модуль Kotlin. Альтернатива — отдельный Kotlin/Compose-клиент, если проба покажет, что это проще для нужных функций. Выбор пока не закреплён.

Настоящий виджет Android реализуется через AppWidget / Jetpack Glance. Состав первой версии: ближайшее событие, 1–3 дела, кнопка открытия ввода, ручное обновление, время свежести данных. Иконка сайта или ярлык не считаются выполнением требования.

Нативный виджет не обязан содержать полноценный редактор. Кнопка «Записать» открывает компактный экран приложения. Фоновое обновление учитывает ограничения Android; точный постоянный интервал не обещается. После действия в приложении обновление виджета выполняется сразу, когда это доступно.

### Windows

Основной сценарий — компактное самостоятельное окно на рабочем столе: события, дела, быстрая запись, сохранение размера и положения, необязательное закрепление поверх окон.

Вариант для исследования: лёгкая оболочка с WebView2 и тем же веб-интерфейсом. Это предложение, не выбранный окончательно стек.

Windows Widgets Board, открываемая через Win+W, — отдельная возможность. Она не заменяет постоянно видимую панель на рабочем столе. Установка собственной программы на рабочий компьютер для использования сайта не требуется.

## 7. Размещение и авторизация

### Что уже найдено

25.11.2026 через подключённый Sites подтверждён проект Health-Check: статус active, владелец имеет доступ, аудитория public, текущий адрес https://health.ltstripes.com, версия 2. Адрес платформы: https://health-check-personal.ltstripes.chatgpt.site.

Таким образом, известный владельцу сайт размещён в ChatGPT Sites. Это не подтверждение наличия отдельного VPS, PHP-хостинга или постоянно работающего Python-сервера. My Day пока не зарегистрирован и не опубликован как Site.

### Кандидат для первого размещения

Отдельный приватный проект My Day в Sites, с сохранением существующего публичного Health-Check. Sites — кандидат, а не окончательный выбор: до реализации нужно проверить работу Drive/Calendar и поддерживаемый доступ Android/Windows-клиентов.

Для размещения в Sites использовать штатную авторизацию платформы через ChatGPT и доступ владельца. Не создавать параллельную систему Google-login поверх штатного входа Sites без подтверждённой необходимости и поддержки. Доступ к подключённому Drive выдаётся отдельно от входа на сайт.

Нативный клиент и фоновые запросы виджета требуют отдельной проверки поддерживаемой авторизации. Нельзя считать, что браузерная сессия автоматически решает этот сценарий, или вшивать сервисный токен владельца в APK. Если платформа не предоставляет подходящий способ, выбрать независимый backend для общих операций. Не обходить ограничения доступа.

Для независимого хостинга достаточно обычного входа через Google с разрешением одному подтверждённому аккаунту и серверной проверкой личности. Система ролей и команд не нужна. Для фоновой работы с Drive понадобится отдельное разрешение и безопасное хранение серверных credentials.

### Доступ с работы

Проверить открытие адреса My Day и выбранной страницы входа в рабочем браузере. Публичный URL не означает публичность заметок. Если корпоративная сеть или политика запрещает нужный сервис, иной пароль не решает ограничение; нужен разрешённый вариант размещения/доступа. Рабочие материалы не входят в исходный личный набор данных.

## 8. Разные модели и локальный ИИ

### Облачные провайдеры

Заложить небольшой интерфейс провайдера: название, модель, способ подключения, возможности. Реализовать одного провайдера, затем добавлять остальные адаптерами. Не предполагать одинаковую поддержку текста, изображений, инструментов и структурированного ответа у всех сервисов.

Настройки владельца: выбрать провайдера и модель для задачи, указать свой ключ в защищённой настройке, проверить соединение, видеть ошибку или отсутствие доступа. Полный ключ не отображать после сохранения и не помещать в браузерный код, APK, Obsidian или Git.

Наличие подписки на чат, API-доступ и история разговоров — отдельные вещи. Логику работы с данными не привязывать к истории чата единственного поставщика.

### На телефоне

Локальная модель может делать короткое резюме, предлагать теги, выделять действие и дату. Сначала эксперимент на реальном телефоне: русский язык, качество извлечения, время ответа, память, размер загрузки, нагрев и работа без сети.

Кандидаты на runtime — LiteRT-LM и llama.cpp для Android. Конкретная модель пока не выбрана. Поддержку системного Gemini Nano на устройстве нельзя предполагать: она зависит от официального списка совместимости.

Локальная модель телефона — отдельный исполнитель. Сайт на работе не получает автоматически доступ к модели в спящем телефоне. Обработка в фоне без активного телефона требует другого доступного исполнителя; облачная передача заметок не включается скрыто при сбое локального режима.

## 9. Что проверить первым

- Можно ли использовать Sites для выбранных Drive/Calendar-действий и отдельного native-клиента.
- Один разрешённый тестовый файл: прочитать, дополнить, перечитать; несвязанный текст и ID сохранены.
- Модель увидела новую запись и изменила разрешённый тестовый материал; сайт получил обновление.
- Домашний ноутбук при этом выключен.
- Отказ сети сохраняет черновик, повтор не дублирует запись.
- Неавторизованный клиент не получает личные данные и не может записать их.
- Результаты теста фиксируются отдельно от макета и документации.
